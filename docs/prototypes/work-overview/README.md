# 工作概览 · 信息结构原型

2026-11-26，低保真交互原型。用浏览器直接打开 [index.html](index.html)，无需安装依赖或启动服务。

[移动端草稿](mobile/index.html)沿用相同的示例工作。可在手机首页直接打开待确认事项，定位异常任务，或按工作浏览并预览交付物。

本次用于评审首屏层级与查找路径，**未替换 Flutter 首页，未接入真实数据**。示例内容固定且虚构，刷新页面会重置演示操作。辅助页面仅标注入口位置。

## 评审重点

- 首页依次呈现「需要我处理 → 当前工作 → 交付物」，三个分区均有首屏直达入口。
- 工作详情提供「概览 / 任务 / 对话 / 交付物」切换；从异常进入任务，从确认事项定位对话上下文，从工作进入文件预览。
- 桌面顶部提供「工作概览」「对话」，右上角进入「更多」。宽度达到 1000px 时，对话正文左侧可切换会话，多文件预览左侧可切换工作文件。小于 720px 时使用底部导航。
- 对话、快速对话与更多中的辅助功能仍有明确位置。

这是对既有导航假设的**提案**。移动端去底栏的现行决策仍见 [§6.115](../../design-decisions/architecture.md)；两端面板族仍保留现有差异。本原型中的分区不表示两端已经实现相同能力。

Skill 的 design-system 与一次 product 重试均未匹配本产品的信息架构，因此未采纳其营销页结构、配色或字体；布局依据 Skill 的通用导航原则及仓库现有数据边界，使用中性灰与本地系统字体。

## 可演示的路径

1. 工作概览 → 待确认事项 → 查看确认 / 查看上下文。点击「演示继续」只移除页面中的示例确认，不改变任务状态。
2. 工作概览 → 异常任务 → 完整任务 / 执行上下文。
3. 工作概览 → 某个工作的交付物 → 只读预览；可对比「本地暂无同步记录」与实际远端清单。
4. 对话 → 按待确认、失败或阻塞筛选已加载工作。
5. 顶部切换正常、空数据、加载中、待确认查询失败、离线缓存、查询结果截断；可切换深色预览。
6. 快速对话 → 输入需求 → 演示提交。内容只在当前页面展示，不发送、不上传、不创建工作。

## 对应现有数据

| 展示 | 现有依据 | 必须保留的口径 |
|---|---|---|
| 工作、目标、当前任务、进度、失败与阻塞 | `ChatGroup.currentGoal`、`GroupGoalSummary` | 只统计已加载列表；任务状态不等于 Agent 此刻在线或正在运行 |
| 跨工作待确认 | `pendingConfirmationsProvider`、`PendingConfirmationSummary` | 排除已失效项；满页显示「至少」；失败与离线不显示成零 |
| 首页文件摘要 | `GroupFileSummary` | 本地同步记录不代表全部远端产物，也不保证本地文件仍存在；空记录不证明没有成果 |
| 工作内文件清单与预览 | `GroupDeliverablesPanel` 及其注入的回调 | 打开工作文件页后按需加载；不为首页逐工作补查远端文件 |
| 确认项上下文 | 现有 `groupId` / `turnId` 锚点 | 返回所属工作和轮次，不只返回整个对话顶部 |

实现依据：[工作摘要](../../../packages/spb_domain/lib/src/group_attention.dart)、[本地文件统计](../../../packages/spb_domain/lib/src/group_file_summary.dart)、[交付物面板](../../../packages/spb_features/lib/src/chat/group_deliverables_panel.dart)。

原型使用本地 JavaScript fixture 演示以上字段与交互，不实例化 Dart 模型、不调用现有 provider。确认过期文案为固定快照示意；真实实现应复用现有过期过滤与刷新机制。没有新增 API、全局执行状态、全局最新交付物接口或系统通知类型。

## 验证与后续

自动化离屏检查覆盖：桌面与手机布局、深浅色、大字号、减少动效、横屏、键盘与 dialog、主要跳转、状态分支和示例输入转义。离屏检查不能替代 Flutter 布局验证或真实用户测试。

10 秒查找任务仍待真人评审，每项从首页开始，记录找到目标入口的耗时与误点：

- 找到一件需要你确认的事，并说明确认内容。
- 找到失败任务，指出它属于哪个工作。
- 找到一个工作的交付物并打开预览，区分远端文件与本地同步记录。

结构验证后，再按现有分层将展示放入 `spb_features`、由两个 app 分别装配数据与导航，并更新正式设计决策和对应测试。
